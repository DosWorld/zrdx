Version 0.50OSE
- The project is moved to free tools: the assembler sources are rewritten for
  NASM 0.98.39, the stub is linked with Watcom wlink, aligner, bin2asm and
  zrxsetup are built with Watcom C. Borland C, TASM, TLINK and MS link are not
  needed any more. The build is done with wmake (see readme.txt).
- The stub is packed with UPX (upx -9 --8086), zrxbind binds the packed stub.
  The prebuilt stub is available as bin\stub-le.exe. The old pack.exe is not
  used by the build any more.
- The settings (zrxsetup) are stored in the last 14 bytes of the bound program
  (signature "ZRXC"), not in the stub header, so the stub can be packed. zrxbind
  writes the default settings block, the stub reads it at start. zrxsetup is
  rewritten; it does not work with programs bound by the older
  zrxbind.
- Support of xle (xeload.asm, zrdxe.asm) is removed.
- Fixed bugs in DPMI function 503h that made it fail when the block has to be
  moved.
- Fixed a bug in zrxbind that made it impossible to bind a pure LE file
  (without an MZ header).
Version 0.49.1
- The maximum value of the transfer buffer that zrxsetup can set is fixed
  (it was ffff, now 1000).
- Minimal changes in zrxsetup.
Version 0.49
- Fixed incompatibility with the beta version of Win 2000 caused by a bug in
  the Win 2000 VDM.
- Fixed a bug in the translation of function 09 of int 33h (set graphics
  mouse cursor).
- The setup parameter "Maximum amount of memory to allocate" works not only in
  XMS but also in RAW mode.
- The setup utility is written.
- The overlay file open mode is changed from "deny none" to "deny write", so
  another task cannot overwrite it while it is being loaded.
- Support of xle is disabled. Use UPX:).

Version 0.48
Fixed bugs:
- In DPMI mode the system stack is shifted when a program is terminated by an
  exception. After this situation is repeated many times the VM system stack is
  completely corrupted and the VM has to be closed (usually it closes itself:)).
  See also below.
- The GDT and IDT limits are set one greater than necessary.

Changes:
- The exception handler is reworked. Now, before the dump is printed and the
  program is terminated, the exception handling mode is left, which usually
  restores the normal state of the system stack. The dump now includes the
  state of the client stack and the value of eip relative to the load address.
- The VCPI+XMS memory allocation mode is introduced: when VCPI pages run out,
  an attempt is made to get and lock a memory block through XMS. This solves,
  in particular, the compatibility problem with the first version of MS EMM386
  in NOEMS mode.

Version 0.47
Fixed bugs:
- The loader calculates the header length with a formula that is not compatible
  with the standard but compatible with wlink.
- The loader hangs when an invalid combination of segment attributes is set.
- The DPMI server considers LDT selectors with RPL other than 3 invalid.

Version 0.46
Fixed bugs:
- When started in RAW/XMS mode with IOPL equal to 0, the program terminates
  abnormally during initialization.

Changes:
- The value of the eflags register is reported in the exception dump.

Version 0.45.

Fixed bugs of version 0.42:
- Support of the 32 bit extension by the DPMI server is not checked. This makes
  initialization impossible when only a 16 bit DPMI is resident.
- Before initialization with the raw/xms methods it is not checked whether the
  processor is in virtual mode. Because of this, wrong behavior is possible
  under a V86 monitor that provides neither VCPI nor DPMI.
- In RAW mode, after the commands that enable A20 are sent to the port, the
  delay needed for A20 to turn on is not long enough. On some computers (quite
  rare ones, though) ZRDX starts only on the second attempt.
- Wrong behavior in RAW mode when there is no memory available through int 15,
  or when A20 cannot be enabled. More precisely, in this case the program
  terminates abnormally with a dump, although the system does not crash.
- The translator of VESA BIOS function 4F00h works incorrectly.
- The DPMI function save/restore processor state for real mode does not work.
- zrxbind in the -r mode always creates a bak file, ignoring the -n key.

New features of version 0.45:
- Direct loading of applications packed with the XLE packer version 1.3.
- The floating point emulator from the Watcom RTL can be used.
- Some parameters can be changed by modifying the stub header, namely:
   - disabling the banner,
   - the order of VCPI/DPMI detection,
   - the length of the transfer buffer,
   - the maximum amount of low memory that must be left free,
   - the maximum amount of memory that can be taken in XMS mode.
- The built-in DPMI emulates direct reading and writing of the control and
  debug registers (DRx, CRx).
- Translation of DOS function 6Ch (open file extended).

Changes in version 0.45:
- Before the message about an exception is printed, the video mode is not
  restored and the screen is not cleared.
- When an exception message is printed for selectors 0-3, "null selector" is
  written instead of "invalid selector".
